=============================

$liveUrl = "https://seat-reservation-service-2kyt.onrender.com"

(Invoke-WebRequest -Uri "$liveUrl/actuator/prometheus" -TimeoutSec 240).StatusCode

readiness = UP

6. TEST DATA REQUIRED
=====================

Reservation load tests require a fresh show and fresh seats.

Recommended test show:

{
  "name": "load-test-show",
  "seats": ["A12","L1","L2","L3","L4","L5","L6","L7","L8"],
  "price_paise": 25000
}

POST /shows requires an ADMIN JWT.

Admin login:

$adminLogin = Invoke-RestMethod -Uri "$liveUrl/auth/login" -Method POST -ContentType "application/json" -Body (@{
    username = "ADMIN_USERNAME"
    password = "ADMIN_PASSWORD"
} | ConvertTo-Json) -TimeoutSec 240

$adminToken = $adminLogin.access_token

Create show:

$show = Invoke-RestMethod -Uri "$liveUrl/shows" -Method POST -Headers @{Authorization="Bearer $adminToken"} -ContentType "application/json" -Body (@{
    name = "load-test-show"
    seats = @("A12","L1","L2","L3","L4","L5","L6","L7","L8")
    price_paise = 25000
} | ConvertTo-Json) -TimeoutSec 240

$showId = $show.id
$showId

IMPORTANT:
Always use a fresh show / fresh hot seat for a new hot-seat test.

15. CANCELLATION LOAD SETUP
===========================

Create a fresh normal user and reserve a fresh seat.

$suffix = [DateTimeOffset]::UtcNow.ToUnixTimeSeconds()
$cancelUser = "cancel_user_$suffix"
$cancelPassword = "LoadTest@123"

Invoke-RestMethod -Uri "$liveUrl/auth/register" -Method POST -ContentType "application/json" -Body (@{
    username = $cancelUser
    password = $cancelPassword
} | ConvertTo-Json)

$cancelLogin = Invoke-RestMethod -Uri "$liveUrl/auth/login" -Method POST -ContentType "application/json" -Body (@{
    username = $cancelUser
    password = $cancelPassword
} | ConvertTo-Json)

$cancelToken = $cancelLogin.access_token

$res = Invoke-RestMethod -Uri "$liveUrl/shows/$showId/reserve" -Method POST -Headers @{Authorization="Bearer $cancelToken"} -ContentType "application/json" -Body (@{
    seats = @("L1")
    idempotency_key = "cancel-setup-$suffix"
} | ConvertTo-Json)

$reservationId = $res.reservation_id

20. CORRECTNESS MODEL
=====================

Redis = contention optimization
PostgreSQL = final correctness authority

The successful reservation decision is made inside a PostgreSQL transaction using pessimistic locking and revalidation.

Multi-seat reservations are all-or-nothing.
Per-user counters are transactionally locked.
Idempotency is stored in PostgreSQL.
Normal contention declines return HTTP 409 rather than HTTP 500.
